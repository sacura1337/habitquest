## 2. Публикация на Amvera Cloud

### Шаг 1. Регистрация

1. Откройте [amvera.ru](https://amvera.ru) и зарегистрируйтесь.
2. Карта не требуется — после регистрации на балансе будет 111 ₽.
3. Списания идут **только за работающие контейнеры**. Пока приложение
   остановлено, баланс не расходуется.

### Шаг 2. Создание приложения

1. В панели откройте **Продукты → Приложения → Создать проект**.
2. Имя проекта: `habitquest-api`.
3. Тип окружения: **Python**. Проект содержит готовый `amvera.yml`, поэтому
   Amvera сама подставит нужные параметры.
4. Тариф: минимальный.

### Шаг 3. Подключение репозитория

Amvera собирает проект из git-репозитория. Возможны два пути.

**Путь А — подключить GitHub (удобнее).** В настройках проекта выберите
подключение существующего репозитория, укажите `sacura1337/habitquest`,
ветку `main` и рабочую директорию **`backend`**. После этого каждый push
в GitHub будет автоматически пересобирать приложение на Amvera.

**Путь Б — push напрямую в Amvera.** Amvera создаёт для проекта собственный
git-адрес. Поскольку бэкенд лежит в отдельной папке, отправляем только её:

```powershell
cd C:\Users\Lytik\Desktop\УП.08
git remote add amvera https://git.msk1.amvera.ru/sacura1337/habitquest-api
git subtree push --prefix backend amvera master
```

Если `git subtree` не работает (он запускает shell-скрипт и в ограниченном
окружении падает), ветку можно собрать средствами самого git:

```powershell
# дерево папки backend превращаем в отдельный коммит
$tree   = git rev-parse HEAD:backend
$commit = git commit-tree $tree -m "Публикация серверной части HabitQuest"
# имя ветки на стороне Amvera указываем полностью
git push amvera "${commit}:refs/heads/master"
```

> Имя ветки Amvera показывает в карточке проекта — обычно это `master`.
> После отправки в логе Amvera появится строка `Detected changes in master branch`,
> и сборка начнётся автоматически.

### Шаг 4. Переменные окружения

В настройках проекта откройте раздел переменных окружения и добавьте:

| Переменная | Значение | Обязательна |
| --- | --- | --- |
| `SECRET_KEY` | длинная случайная строка, минимум 32 символа | да |
| `ALGORITHM` | `HS256` | да |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` (7 суток) | да |
| `CORS_ORIGINS` | `https://sacura1337.github.io,http://localhost:5173` | да |
| `DATABASE_URL` | `sqlite:////data/habitquest.db` | нет |
| `UPLOAD_DIR` | `/data/uploads` | нет |

Случайный ключ удобно получить так:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

**Никогда не вписывайте эти значения в файлы репозитория** — только в переменные
окружения хостинга.

**Почему SQLite, а не PostgreSQL.** На бесплатном балансе выгоднее держать один
контейнер вместо двух: приложение и база живут вместе, а файл базы лежит на
постоянном хранилище `/data` и переживает пересборку. Переключение на PostgreSQL
выполняется одной переменной — код поддерживает оба варианта:

```text
DATABASE_URL=postgresql://пользователь:пароль@хост:5432/habitquest
```

### Шаг 5. Доменное имя

При создании проекта Amvera сразу заводит домен со **внутренним** типом
подключения. Из интернета он недоступен — соединение отбрасывается ещё до
установки шифрования, поэтому ни браузер, ни curl приложение не увидят.

Чтобы сайт открывался снаружи, перейдите во вкладку **«Домены»** и нажмите
**«Создать доменное имя»**:

| Поле | Значение |
| --- | --- |
| Тип подключения | `HTTPS` |
| Тип домена | `Бесплатный домен Амвера` |
| Доменное имя | предложенное Amvera, например `habitquest-api-sacura1337.msk1.amvera.tech` |
| Дополнительные настройки → Порты | **оставить пустыми** — приложение слушает один порт |

Сертификат Amvera выпускает автоматически, домен начинает отвечать через
одну-две минуты.

### Шаг 6. Проверка

Рабочий адрес проекта: **https://habitquest-api-sacura1337.msk1.amvera.tech**

```powershell
# 1. Сервис отвечает
curl.exe https://habitquest-api-sacura1337.msk1.amvera.tech/

# 2. Документация API открывается
start https://habitquest-api-sacura1337.msk1.amvera.tech/docs

# 3. Вход тестовым аккаунтом
curl.exe -X POST https://habitquest-api-sacura1337.msk1.amvera.tech/api/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"email\":\"demo@habitquest.ru\",\"password\":\"demo1234\"}"
```

Третий запрос должен вернуть `access_token`, `token_type` и объект `user`.

### Шаг 7. Связь с фронтендом

Фронтенд уже опубликован: **https://sacura1337.github.io/habitquest/**

1. В переменных окружения бэкенда должно быть:
   `CORS_ORIGINS=https://sacura1337.github.io,http://localhost:5173`
   Без этого браузер заблокирует запросы с сайта к API.
2. Подключение фронтенда к API — задача следующего этапа. Адрес бэкенда
   передаётся в сборку переменной `VITE_API_URL` через переменные репозитория
   GitHub: **Settings → Secrets and variables → Actions → Variables**.

## 3. Баланс и ограничения Amvera

| Ограничение | Как проявляется | Что делать |
| --- | --- | --- |
| Баланс конечный | 111 ₽ — стартовый бонус. Когда он закончится, приложение остановится | Останавливайте проект, когда он не нужен: списания идут только за работающие контейнеры |
| Одна реплика | Горизонтального масштабирования на минимальном тарифе нет | Для учебного проекта не требуется |
| Холодный старт | После остановки первый запрос идёт дольше обычного | На защите откройте сайт заранее |

## 4. Альтернативные хостинги

| Хостинг | Условия | Подходит ли |
| --- | --- | --- |
| **Hugging Face Spaces** | Бесплатно бессрочно, без карты, Docker | Да, но данные на диске не сохраняются между пересборками, а доступность из РФ нестабильна |
| **Render** | Нужна иностранная карта | Нет — недоступно без карты |
| **ONREZA** | Бесплатный тариф без карты | Нет — поддерживаются только JavaScript-фреймворки |
| **CloudPub** | Бесплатный туннель к вашему компьютеру | Резервный вариант: компьютер должен быть включён во время защиты |
| **Собственный VPS** | Полный контроль, платно | Нужны nginx, systemd и PostgreSQL вручную |

Для любого Docker-хостинга подойдёт готовый `backend/Dockerfile`:

```bash
docker build -t habitquest-api backend
docker run -p 8000:8000 --env-file backend/.env habitquest-api
```

### Render (если появится иностранная карта)

В репозитории сохранён `render.yaml` с описанием веб-сервиса и базы PostgreSQL.
Развёртывание: **New → Blueprint** → выбрать репозиторий `habitquest` → **Apply**.

| Поле | Значение |
| --- | --- |
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `alembic upgrade head && python -m app.seed && uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/` |
